# 速闻内容规范

本文给人工编辑、自动生成和 iOS App 共用。每天产出的不是一篇网页，而是一组**可独立定位的新闻条目**。App 按条目做列表、详情、收藏和分享。

旧的整页 `index.html` + CSS 标签页 + 语音速览已经废弃。不要再生成 `briefing.m4a`。

---

## 0. App 怎么读这些文件

```
https://raw.githubusercontent.com/zhipengge/apps/main/speed/contents/
```

仓库目录：

```
apps/speed/contents/
├── catalog.json
├── 20260821/issue.json
└── 20260822/issue.json
```

| App 行为 | 对编辑的含义 |
|---|---|
| 默认打开当前窗口那一期 | 目录名 `YYYYMMDD` 覆盖前一日 12:00 至当日 12:00（`Asia/Shanghai`） |
| 先读 `catalog.json` | 新增或下架一期必须改清单 |
| 先展示本地缓存，再静默回源 | 改完 `issue.json` 推到 `main` 即可 |
| 每条新闻有稳定 `id` | 收藏、分享、跨设备导入都靠这个 id，发布后不要改 |
| 点出处在 App 内打开 | `source.url` 必须是可打开的 `https://`（政府站可用 `http://`） |
| 分享只走微信友好文稿 | 条目必须能单独导出：标题、简介、正文、出处、日期、板块 |

`catalog.json` 只放 8 位数字日期，升序：

```json
["20260821", "20260822"]
```

也接受 `{"dates":["20260821","20260822"]}`。

## 1. 一期一份 JSON

路径：`speed/contents/YYYYMMDD/issue.json`

```json
{
  "schemaVersion": 1,
  "dateKey": "20260822",
  "lead": "一句话总述本窗口最值得看的几件事。",
  "articles": []
}
```

| 字段 | 要求 |
|---|---|
| `schemaVersion` | 当前为 `1` |
| `dateKey` | 必须和目录名相同 |
| `lead` | 能独立成立，不要写成栏目目录 |
| `articles` | 12–20 条。五个板块都要有，每板块至少 2 条 |

不要写语音播报、不要附整页 HTML、不要把互不相关的新闻揉进一条。

## 2. 一条新闻

```json
{
  "id": "20260822-pol-china-indonesia-csd",
  "category": "politics",
  "cluster": "战略对话",
  "title": "中印尼全面战略对话首次会议在雅加达举行",
  "summary": "王毅与印尼外长共同主持机制首次会议，双方启动制定 2027–2031 五年行动计划。",
  "body": [
    "先写发生了什么。",
    "再写为什么重要、边界在哪里。",
    "数字给单位和截止日期。"
  ],
  "image": {
    "url": "https://images.unsplash.com/photo-xxxx?auto=format&fit=crop&w=1200&q=80",
    "alt": "用一句话说明画面",
    "caption": "图说来源或场景，不超过 40 字。"
  },
  "source": {
    "name": "新华社",
    "url": "https://www.news.cn/...."
  },
  "publishedAt": "2026-08-21T18:57:00+08:00",
  "eventAt": "2026-08-21T18:57:00+08:00"
}
```

| 字段 | 要求 |
|---|---|
| `id` | `{dateKey}-{板块缩写}-{英文短slug}`。全库唯一，发布后冻结 |
| `category` | 只能是 `tech` / `politics` / `military` / `finance` / `entertainment` |
| `cluster` | 2–6 个汉字，板块内聚类名 |
| `title` | 结论先行，不超过 28 字 |
| `summary` | 40–80 字，列表页只靠它就能读懂 |
| `body` | 3–6 段，每段 60–160 字。这是阅读正文，不是标题复读 |
| `image` | 必须有。用 Unsplash / Wikimedia / 自家图，禁止热链新闻社原图 |
| `source.name` | 媒体或机构名 |
| `source.url` | 可点开的原文 |
| `publishedAt` | 见报时间，ISO 8601，东八区 |
| `eventAt` | 事件发生时间；窗口外事件必须同时写清 |

可选：`audio`（`url` + `caption`）。只给这条新闻自己的现场录音或官方音频，**不要**再做整期口播。

板块缩写：`tech` `pol` `mil` `fin` `ent`。

## 3. 时间窗口

| 项目 | 要求 |
|---|---|
| 窗口 | 发布日前一日 12:00 至发布日 12:00 |
| 示例 | `20260822` 覆盖 2026-08-21 12:00 — 2026-08-22 12:00 |
| 跨窗口 | 可以跟进，但必须同时写事件时间和见报时间 |
| 尚未发生 | 预告可以写，不得写成已经发生 |
| 休市 | 财经数字写到窗口内最后一个已收盘交易日 |

目录名、`dateKey`、每条 `id` 前缀必须是同一天。

---

## 4. 文风

- 中文简体。先结论后背景。
- 每条新闻是独立阅读单元，不要「详见上一篇」。
- 不确定标「尚待确认」。不编造引语、报价、伤亡和选举结果。
- 财经不荐股。政治、军事克制。
- 同一窗口互相矛盾的稿件，写双方主张，不自行裁断。

---

## 5. 发布检查

- [ ] `contents/YYYYMMDD/issue.json` 存在，`dateKey` 一致
- [ ] `catalog.json` 已写入该日期
- [ ] 无整页 HTML、无整期语音播报
- [ ] 五板块都有，每条有稳定 `id`、标题、简介、正文、图、出处、时间
- [ ] 正文足够独立阅读，不是一句话标签
- [ ] 图片有 `alt`，来源链接能打开
- [ ] 预告未写成已经发生
- [ ] 没有 `.DS_Store` 或 `*_副本`
