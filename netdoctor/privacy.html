中文

这是一个网络诊断工具，它必须碰网络——这一点我们不绕开说。 它对外只有三种动作，全部是只读探测：DNS 查询、TCP 连接（发个 SYN 就关，不带任何业务数据）、ICMP 回声。它没有 HTTP 客户端，不下载任何网页，不上传任何东西，不向我们的服务器发送任何数据——因为没有我们的服务器。 它采集什么、发到哪里，下面逐条写清楚。同时，「只诊断、不修改」不是一句承诺，是结构性的：整个工程里不允许出现任何写系统网络配置的 API，这条由脚本机械检查，每次跑测试都会验一遍。

它会往网络上发什么

App 对外只有下面三种动作。三种都是只读的，都不携带任何可以指认到你或你这台设备的信息：没有账号、没有设备标识符、没有安装 ID、没有请求正文、没有表单、没有参数。

动作具体做什么发给谁
DNS 查询自己构造一个标准的 DNS 报文（RFC 1035 格式），通过 UDP 53 端口发出，问一个域名解析成什么地址。另发一个新 ID 的查询，不复用缓存结论。你系统里配置的 DNS 服务器（从系统网络配置里读出来的那些），同时也会问一次系统解析器做对照
TCP 连接发起一次 TCP 握手，连上就立刻关闭。在应用层不发送任何一个字节，没有 HTTP 请求，没有 TLS 协商，没有业务数据。连接被对方拒绝（返回 RST）同样算作「主机是活的」。你的局域网网关，以及几个公开的公共服务地址（见下）
ICMP 回声就是 ping。用非特权 ICMP 发（普通用户权限即可，不需要管理员，不装后台守护进程）。你的局域网网关

被探测的具体目标只有这几类：

  • 你自己的网关地址，以及你系统里配置的 DNS 服务器——这两个都是从你的系统网络配置里读出来的，不是写死的。
  • 两个公开的公共 DNS 服务地址（直连 IP，不经过域名解析），用来区分「路由坏了」和「DNS 坏了」。
  • 一个公开的强制门户探测域名，用来验证解析这一层。
  • 四个公开的服务域名，用来回答「我这边通，是不是只有某个服务不通」。

以上都是公开可访问的地址，不涉及任何需要登录的接口。完整的目标清单写在源码里，任何人都可以去核对。目标列表里没有任何一个属于开发者——这个 App 没有自建服务器，也没有遥测端点。

所以「连了谁」这件事不构成隐私问题：这些探测不带任何业务数据、不带任何标识，对端看到的只是一次普通的 DNS 查询或一次握手——和你的系统自己会做的事没有区别。App 也不会把「你连过谁」记录下来发往别处。

菜单栏那个数字

App 常驻菜单栏，显示一个延迟数字。它的来源是每 10 秒一次 TCP 握手，对象是上面那两个公共 DNS 地址之一，连上就关。屏幕休眠时这个定时器会被停掉，醒来才补一次——没人在看的时候它不跑。

它读你本机的什么

为了知道「你的网关是谁、DNS 配的是哪几个、网卡有没有拿到地址」，它会只读地查询系统网络配置：当前网络服务、接口列表、IP 地址与掩码、路由器地址、DNS 服务器列表、代理设置、以及系统解析器配置文件。

这些都是读操作，一个字节都不改。 这一条不是靠自觉：

  • 黑名单：脚本在全部源文件里搜 23 个写入型 API（改配置、提交变更、改路由、改 DNS、改 hosts 之类），出现任何一个就失败。写在注释里提到某个 API 不算调用——脚本会先去掉注释再看。
  • 白名单反查：所有系统网络配置的调用都必须在 9 个只读接口的名单里，防止有人调了一个黑名单里没想到的写接口。
  • 这个检查每次跑测试都会执行，不是一次性的人工核对。

换句话说：App 里连「顺手帮你改一下 DNS」的入口都不存在，不是「有但不建议用」。你装的是一个只看不动的工具。

我们处理什么、存在哪

数据用途位置
诊断历史：最近 50 次的轻量记录（时间、每层的结论、关键耗时）。不保存完整报告正文，那份几十行原始数据只在导出时生成。回答「上次什么时候出的问题」本机的 UserDefaults，单键 netdoctor.history.v1；可单条删除，也可一键清空
界面偏好（刷新节奏等设置）记住你的偏好本机 UserDefaults
你导出的报告给你一份可以发给别人的纯文本由你在系统保存面板里选位置，写成一个 .txt 文件。除此之外 App 不写任何文件

历史记录里有时间、有你这次测出来的网络质量——这些数据只在本机，不会同步、不会上传、不会分享给任何人。删除即消失，别处没有副本。

我们不做什么

  • 不修改你的任何系统网络设置：不改代理、不改 DNS、不改路由、不改 hosts、不开关网卡。工程里连这类 API 都不允许出现。
  • 不发送任何业务数据：探测就是一次 DNS 查询或一次 TCP 握手，没有请求正文。
  • 不向任何服务器回传数据：没有我们的服务器，没有遥测，没有统计，没有广告，没有崩溃上报，没有检查更新。
  • 不要求注册或登录，没有账号系统。
  • 不读取你的文件、照片、通讯录、日历、位置、麦克风、摄像头。
  • 不申请任何系统权限，系统不会为它弹出授权框（详见下节）。

权限

App 不申请任何系统权限，也不会弹出授权框。

  • 沙盒授权一共只有两条：沙盒本身，和出站网络客户端。没有别的。
  • 不写文件——导出报告走系统保存面板，那是你主动选的一次动作。
  • 不读你的用户目录，不申请完全磁盘访问。
  • 没有 App Group，没有扩展，没有共享容器。
  • 它不需要辅助功能，也不需要输入监控：它不模拟点击、不监听键盘、不控制其它应用。面板里的按键都是普通的界面按键。
  • ICMP 用的是非特权模式，不需要管理员权限，也不安装任何后台服务或守护进程。

第三方

App 里没有任何第三方代码。 没有依赖包、没有内嵌框架，界面图标一律用系统符号。没有广告、没有分析统计、没有崩溃上报、没有追踪 SDK。

本 App 在设计时读过几个开源同类项目（系统监视器、DNS 诊断工具、菜单栏 ping 工具）的文档与源码用于借鉴设计思路，但一行代码都没有复制，一个素材都没有取用。其中有一个项目带了 GPL 许可，它的代码完全没有被接触。

加密

App 不做任何加密、哈希或密钥运算，也没有链接密码学框架。它本身不发起 HTTPS 连接，因此不涉及传输加密。出口合规申报为不使用非豁免加密。

数据删除

历史记录可以单条删除，也可以在界面上一次清空。因为数据只在这台电脑上，删掉之后别处没有副本可以残留。删除 App 即清除全部数据。

儿童

本 App 不收集任何人的数据，当然也不收集儿童的数据。它没有账号、没有聊天、没有用户生成内容，也不向任何服务器回传信息。

这份政策和代码的对应关系

上面每一条声明都对应到工程里的具体实现，而不是一份套用的模板。如果你要核对：探测的判定逻辑集中在一个纯函数里（可离线跑测试），三种探针各占一个文件，只读检查是一个可以随时自己跑的脚本。App 里显示的「只读模式：不修改你的任何系统网络设置」这句话，和这份政策说的是同一件事。

English

This is a network diagnostic tool, so it does touch the network, and we will not dance around that. It has exactly three outbound actions, all read-only: a DNS query, a TCP connection (send a SYN and close immediately, carrying no application data whatsoever), and an ICMP echo. It contains no HTTP client, downloads no pages, uploads nothing, and sends nothing to a server of ours, because there is no server of ours. What it collects and where it goes is set out below. And "diagnose only, never modify" is not a promise, it is structural: the project does not permit any API that writes system network configuration, and a script checks that mechanically on every test run.

What it sends onto the network

The app has exactly three outbound actions. All three are read-only, and none of them carries anything that identifies you or this machine: no account, no device identifier, no installation ID, no request body, no form, no parameters.

ActionWhat it doesWhere it goes
DNS queryBuilds a standard DNS message itself (RFC 1035 format) and sends it over UDP port 53 asking what address a name resolves to. Each diagnostic sends a fresh query with a new ID rather than reusing a cached answer.The DNS servers configured in your system, read out of your network settings, plus one comparison query through the system resolver
TCP connectionOpens a TCP handshake and closes it immediately on success. At the application layer it sends not a single byte: no HTTP request, no TLS negotiation, no application data. A connection refused with RST also proves the host is alive.Your local gateway, and a few public service addresses (below)

The targets it probes fall into just these categories:

  • Your own gateway and the DNS servers configured in your system. Both are read out of your network configuration rather than hard-coded.
  • Two public DNS service addresses (connected by IP, bypassing name resolution), used to tell "the route is broken" apart from "DNS is broken".
  • One public captive-portal detection domain, used to verify the resolution layer.
  • Four public service domains, used to answer "my side is fine, is it just one service that is down".

All of them are publicly reachable and none requires a login. The complete target list is in the source, where anyone can check it. None of the targets belongs to the developer: this app has no server of its own and no telemetry endpoint.

So "who did it connect to" is not a privacy question here. These probes carry no application data and no identifier; the other end sees an ordinary DNS query or handshake, indistinguishable from what your system does on its own. The app also does not record who you connected to and send it anywhere.

The number in the menu bar

The app sits in the menu bar showing a latency figure. It comes from one TCP handshake every ten seconds to one of the two public DNS addresses, closed as soon as it connects. That timer stops when the screen sleeps and catches up on wake, so it does not run while nobody is looking.

What it reads from your machine

To know who your gateway is, which DNS servers are configured, and whether the interface has an address at all, it read-only queries your system network configuration: the active network service, the interface list, IP addresses and netmasks, the router address, the DNS server list, proxy settings, and the resolver configuration file.

All of these are reads. Not one byte is modified. That is not left to good intentions:

  • A blacklist: a script searches every source file for 23 write-type APIs (changing configuration, committing changes, altering routes, DNS or hosts) and fails if any appears. An API merely mentioned in a comment does not count, because the script strips comments first.
  • A whitelist cross-check: every system network configuration call must be one of nine read-only functions, which catches anyone reaching for a write API the blacklist did not anticipate.
  • That check runs on every test run, not once by hand.

In other words, the app does not even contain an entry point for "just quietly change your DNS". It is not that the feature exists and is discouraged; it does not exist. What you install is a tool that only looks.

What we do not do

  • We do not modify any of your system network settings: no proxy changes, no DNS changes, no route changes, no hosts edits, no toggling interfaces. Such APIs are not even permitted to appear in the project.
  • We send no application data: a probe is a DNS query or a TCP handshake, with no request body.
  • We report nothing back to any server: no server of ours, no telemetry, no analytics, no ads, no crash reporting, no update check.
  • No registration or sign-in and no account system.
  • No reading of your files, photos, contacts, calendar, location, microphone or camera.
  • No system permissions are requested, so the system never prompts you (see below).

Permissions

The app requests no permissions and never shows a permission prompt.

  • The sandbox declares exactly two things: the sandbox itself and the outbound network client. Nothing else.
  • No file writes; exporting a report goes through a system save panel, which is an action you take.
  • No access to your home folder and no Full Disk Access.
  • No App Group, no extensions, no shared container.
  • It needs no Accessibility and no Input Monitoring: it does not simulate clicks, does not listen to the keyboard, and does not control other apps. The keys in its panel are ordinary interface keys.
  • ICMP is used in unprivileged mode, so no administrator rights are needed and no background service or daemon is installed.

Third parties

The app contains no third-party code. No dependencies, no embedded frameworks; interface icons are all system symbols. No ads, no analytics, no crash reporting, no tracking SDKs.

While designing this app we read the documentation and source of several open-source peers (a system monitor, a DNS diagnostic toolkit, a menu bar ping tool) to learn from their design decisions. Not one line of code was copied and not one asset was taken. One of them carries a GPL licence; none of its code was touched at all.

Encryption

The app performs no encryption, hashing or key handling and links no cryptography framework. It does not itself make HTTPS connections, so no transport encryption is involved. Export compliance is declared as using no non-exempt encryption.

Deletion

History entries can be deleted individually or cleared entirely from the interface. Because the data is only on this computer, there is no copy elsewhere to linger. Deleting the app removes everything.

Children

The app collects no one's data, children included. It has no accounts, no chat, no user-generated content, and reports nothing to any server.

How this policy maps to the code

Every statement above corresponds to something specific in the project rather than being adapted from a template. If you want to check: the diagnostic verdicts live in one pure function that can be tested offline, the three probe types each occupy a file, and the read-only check is a script you can run yourself at any time. The line the app displays, that it is read-only and will not modify your system network settings, says the same thing this policy does.
