文辑 — 帮助与支持

WeEdit Support · 需要 macOS 14.0 或更高版本 / Requires macOS 14.0 or later

中文

一篇稿写给公众号、小红书、知乎、微博。切换平台后按对方的规则改成对应的 HTML 或纯文本，复制，到网页后台粘贴。文辑不登录这些平台的账号，也不代你发布。

怎么用

  1. 左边新建文稿，中间写正文：文字、加粗斜体、颜色、引用、列表、图片、表格、并排图、视频音频占位
  2. 顶上选要发的平台，右侧会显示适配结果和这个平台吃不下的地方
  3. 点「复制并打开后台」，系统浏览器会打开对应的创作页
  4. 在那边的编辑器里粘贴（Command+V）

也可以只点「复制适配稿」自己打开后台，或者「导出 HTML」存成文件。文稿在你写的当下就存下来了，不需要手动保存。

常见问题

为什么不能一键发布？

这些平台没有给第三方 App 用的稳定发文接口。文辑不登录你的账号、不代发，换来的是格式由你自己控制、稿件不经过我们的服务器。省下的是重新排版的时间，不是发布的时间。

粘过去图片不见了或变成红叉？

请用工具栏的「复制适配稿」，不要只在编辑区里手工选中再复制。文辑复制时会把本地图片嵌进 HTML 里一起带走，这是为了绕开平台对外链图片的拦截；手工选中复制拿不到这一步。小红书和微博还会把图片作为独立的一项放进剪贴板，用来配合它们各自的图片上传框。

表格和并排图为什么在小红书、微博没了？

因为那两个平台根本不接受表格。文辑不会假装能带过去：表格会被转成纯文字，并排图会拆成逐张，并在提示里告诉你发生了什么。

视频和音频为什么只是一块说明？

这四个平台都不接受随正文粘贴的视频文件，音频更是完全不支持。文辑在这里写一块说明文字，是因为如果做成空的播放器占位，粘贴过去通常就是一块裂图，说明块至少告诉读的人这里本来有什么。

从公众号复制一篇文章粘进来，段落挤在一起了？

已知问题。公众号的正文大量使用 section 包段落，而文辑解析 HTML 用的系统组件不认这个标签，会把容器拆掉，里面的文字并到一起。同一条也影响从别的富文本编辑器粘复杂结构。正在考虑怎么修。

微博正文段与段之间空得比原稿多？

已知问题。微博导出会把换行写成两个换行，所以每段之间会多出一个空行，只有图没有字的时候开头还会多一个空段落。不影响能不能发，但显示上比原稿松。

文稿存在哪？换电脑怎么办？

在沙盒容器的 Application Support/WeEdit/Documents/ 里，每篇稿是一个以文稿编号命名的目录，里面是 article.json 和一个 media/ 目录。想备份或迁到别的机器，整个 Documents 目录拷走即可，文稿和图片在一起，没有外部依赖。

想彻底删掉？

退出文辑，从「应用程序」删除它，再移除 ~/Library/Containers/com.gezhipeng0201.WeEdit。稿子就在这个容器里，删掉即无残留。

关掉窗口了，进程还在吗？

不在。文辑是单窗口工具，关闭最后一扇窗口时退出。它不是菜单栏常驻程序，不会留在后台。

断网能用吗？

能写、能存、能切平台、能复制。断网时唯一受影响的是文稿里那些本来就在网上的图片，它们显示不出来，复制出去的 HTML 里保留的还是原地址；另外「打开后台」需要浏览器联网。

它要什么权限

沙盒授权一共三条：App 沙盒本身、你选定的文件（读与写）、出站网络。除此之外不需要任何权限，没有辅助功能、没有输入监控、没有完全磁盘访问、没有通知、没有自动化，不碰通讯录和位置，不用麦克风和摄像头。它也不做跨 App 追踪。

已知不足

  • 四个后台的真机粘贴回归还没做过。格式和图片能不能顺利过，目前是按代码和逻辑测试推出来的，还没有在四个网页后台里各粘一次。这是交付前明确列出的待办，我们不想把它说成「已经验证」。
  • 输入侧是空的。不能导入 markdown、docx，也不能抓网址，稿子只能手打或从浏览器粘贴。文辑不是写作工具，是临发之前那一步的工具。
  • 编辑器不是专业排版工具。它是网页里的可编辑区域，字体、行距、分页、导出 PDF 这些都不如专业写作软件，也没打算做。
  • 只发一个平台的人用不上它。没有第二个平台要适配，收益就是零。这一条我们写在明面上。
  • 「同一篇稿子要发多个平台」这个前提还没有被真实用户验证过。平台规则差异是代码里查得到的，但有多少人愿意为省这一步装一个 App，目前没有证据。

反馈

请到项目仓库的 Issues 说明三件事：系统版本、目标平台、问题是出在复制这一侧还是对方编辑器那一侧。有具体的文稿结构（比如某段用了表格还是并排图）会更好定位。

English

One draft for WeChat Official Accounts, Xiaohongshu, Zhihu and Weibo. Switching platform rewrites it into HTML or plain text that editor accepts, and you paste it into the web editor. WeEdit never signs in to these platforms and never posts for you.

How to use it

  1. Create a draft on the left and write in the middle: text, bold and italic, colour, quotes, lists, images, tables, side-by-side image rows, video and audio placeholders
  2. Pick a platform at the top; the right side shows the adapted result and what that platform will not take
  3. Press copy and open editor, and the browser opens that platform's compose page
  4. Paste there (Command+V)

You can also copy the adapted draft and open the site yourself, or export the HTML to a file. The draft is saved as you type; there is no save button.

Common questions

Why can it not publish in one click?

These platforms offer no stable third-party publishing API. WeEdit does not sign in or post on your behalf; in exchange, the formatting stays under your control and the draft never passes through a server of ours. What it saves is reformatting time, not publishing time.

Images are missing or broken after pasting?

Use the copy adapted draft button rather than selecting text in the editor by hand. Copying inlines images stored with the draft into the HTML so platform hotlink blocking does not break them, and selecting by hand skips that step. For Xiaohongshu and Weibo the images are also placed on the pasteboard as separate items, to match their upload boxes.

Where did tables and side-by-side images go on Xiaohongshu and Weibo?

Those two platforms do not accept tables at all. WeEdit does not pretend otherwise: tables become plain text, side-by-side rows are split into separate images, and a warning tells you what happened.

Why is video just a note?

None of the four platforms accepts a video file pasted with the body text, and audio is not supported at all. A note is written instead, because an empty player placeholder usually arrives as a broken image; the note at least tells the reader something was there.

Text pasted from a published WeChat article runs together?

Known issue. WeChat articles wrap paragraphs in section, which the system HTML parser does not recognise, so the container is flattened and the text merges. The same applies to complex structures copied from other rich-text editors. A fix is being considered.

Weibo paragraphs have extra blank lines?

Known issue. The Weibo export writes each line break as two, so there is an extra blank line between paragraphs, and a draft with images but no text starts with an empty paragraph. It still publishes; it just looks looser than the original.

Where are drafts stored, and how do I move them?

In the sandbox container under Application Support/WeEdit/Documents/, one folder per draft, each holding article.json and a media/ folder. Copy the whole Documents folder to back up or move machines: text and images travel together with no external dependency.

How do I delete everything?

Quit WeEdit, remove it from Applications, then remove ~/Library/Containers/com.gezhipeng0201.WeEdit. The drafts live in that container; removing it leaves nothing behind.

Does it keep running after I close the window?

No. WeEdit is a single-window tool and quits when you close its last window. It is not a menu bar agent.

Does it work offline?

Writing, saving, switching platforms and copying all work offline. The only things that need a connection are remote images already in a draft, which simply will not display, and opening a platform editor.

Permissions

The sandbox grants exactly three things: the sandbox itself, user-selected files (read and write), and outbound network. Nothing else is requested: no Accessibility, no Input Monitoring, no Full Disk Access, no notifications, no automation, no Contacts or Location, no Microphone or Camera, and no cross-app tracking.

Known limitations

  • The four web editors have never been round-tripped by hand. Whether the formatting and images survive is currently derived from the code and the logic tests; they have not been pasted into each of the four real editors yet. It is listed as an open item, and we would rather not call it verified.
  • The input side is empty. No markdown or docx import and no URL capture, so text is typed here or pasted from a browser. WeEdit is not a writing tool; it covers the step just before publishing.
  • The editor is not a typesetting tool. It is a web view's editable area, and fonts, line spacing, pagination and PDF export are all well short of a dedicated writing application, by design.
  • If you publish to one platform, this app is not for you. With no second format to adapt, the gain is zero, and we say so.
  • The premise itself is unvalidated. The platform differences are verifiable in code, but whether people will install an app to save this step has no evidence behind it yet.

Feedback

Please open an issue in the project repository with three things: the system version, the platform you were targeting, and whether the problem is on the copying side or in the other editor. A description of the structure, such as whether the passage had a table or side-by-side images, helps a lot.
