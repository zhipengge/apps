中文

它是干什么的？

把一组要一起打开的东西（应用、本地文件或文件夹、网址）存成一个场景。进入之前它先探一遍这些地址通不通，离开的时候你留一句话当断点，下次进来第一眼就告诉你上次停在哪。

怎么用？

点菜单栏图标开面板。面板里是场景列表，点一下就进入。设置里可以给场景配上快捷键，最多九个，对应场景列表的前九个。

「进入场景」具体做了什么？

按固定顺序来：先应用、再文件、最后网页。先让应用起来，再把文件交给它，最后开网页，这样浏览器不会抢在前面把焦点占掉。已经在运行的应用不会再拉起一次，所以重复进入同一个场景是安全的。

进入前那个体检是什么？

对场景里的每个网址发一个探测请求，只拿响应头就断开，正文一个字节都不收（不是把整个页面下下来再丢掉）。然后按失败原因告诉你下一步该做什么：

结果通常意味着会不会拦住你
正常服务是通的不拦
要登录（401 / 403 / 407）服务是通的，只是需要登录不拦，照常进入
限流（429）请求太频繁，但服务在不拦
地址失效（404 / 410）路径变了不拦，只提示
被拒（其它 4xx）对方拒绝了这次请求不拦，只提示
服务报错（5xx）服务在，但它自己出问题了不拦，只提示
解析失败域名解析不了，最常见的原因是没连上内网或 VPN拦
连不上服务没起来，或者地址写错了拦
证书没通过中间有代理在拦拦
超时对方没在 6 秒内回应拦
没有网络这台机器本身没联网拦

只有明确打不开的才拦，而且默认不打开它——因为它在浏览器里也只会是个错误页。其余情况一律放行，只是把结果标出来。

「要登录」被当作正常，这一条是刻意的。 把「需要登录」误判成「打不开」，用户就不会再信任这个功能了。

断点是什么？

你离开场景时留的一句话，加上那一刻的现场快照。快照只记一件事：这个场景里的哪些应用还在跑、哪些已经退了。它不记浏览器标签页——那是它看不到的东西，不假装看得到。每个场景保留最近 5 条断点。

可以放多少个场景、每个场景多少条？

场景总数上限 60，单个场景的条目上限 40。一次进入超过 12 条会先提醒你一次，但仍然可以继续。这些限制防的是「一键打开 60 个标签页」这种自伤操作。

我的数据存在哪？换台机器怎么办？

整份文档以一个 JSON 存在本机，没有云端，没有同步，没有 iCloud。所以「备份与迁移」页把导出放在最显眼的位置：导出的是一份纯文本 JSON，你可以自己看、自己改。导入只合并不清空——不会拿导入的文件把你现有的场景盖掉。

卸载 App 数据会没吗？

会。数据只在这台电脑上，卸载即清除，别处没有副本。想留就先导出。

它需要什么权限？

不需要任何系统权限，也不会弹授权框。 特别说明一条：它不需要辅助功能，也不需要输入监控——全局快捷键走系统的热键注册，由系统代管。它也不会去控制其它应用的窗口：不做窗口布局，不摆窗口位置，不模拟点击。详见隐私政策。

它联网吗？

只在一个地方：连通性巡检，也就是进入场景前的自动体检和你手动按下的「体检」。这个请求只发给你自己场景里填的地址，App 里没有我们的服务器，没有统计，没有检查更新，也没有崩溃上报。请求是 GET 加一个只取 1 字节的 Range 头，拿到响应头就断开；会话是无痕的，cookie 和磁盘缓存都关着，所以巡检过哪些地址不会在本机留下痕迹。

我选了本地文件，它会不会去读我的文件内容？

不会。选文件这件事由你在系统面板里完成，App 不会自己去翻磁盘，也没有「扫描目录」这类功能。存下来的访问凭证是只读的，用途只有一个：下次进入场景时把它交给系统打开，相当于帮你双击一下。

为什么它会在我点到别处的时候收起来？

因为面板是临时弹出式（transient）的，这是菜单栏应用的正常行为。代价是没有为「需要长时间停留」的场景做优化——比如你想一边看体检结果一边去别处复制点什么，面板会先收起来。这一条如实说明。

支持哪些系统？

需要 macOS 14.0 或更高版本。它是菜单栏应用，不占 Dock 图标。

已知不足

以下几条是作者自己标注的，写在这里而不是藏起来：

  • 没有做鼠标点击级别的端到端验证。 演示钩子走的是真实代码路径（真实的探测、真实的进入逻辑），但「用手点那个按钮」这一步没有验过。
  • 带系统弹窗的路径完全没有验过：选文件、选应用、导出、导入——因为这四个都会弹授权面板。如果你在这几条路径上遇到问题，那很可能就是还没被覆盖到的地方，请务必反馈。
  • 位置写错的表现：面板是临时弹出式的，点到别处就收，长时间停留在面板上的用法没有被专门照顾。

App 本身的功能是完整的，没有半成品；上面说的是「没有被验证到的部分」，不是「没做完的部分」。

设计取舍

这个 App 的差异很窄，如实说：它对「每次开工前要先确认一组内网或线上服务通不通」的人有意义——运维、后端、要连 VPN 的人、同时维护好几套环境的人。如果你只是「想快点打开几个网页」，那么通用的启动器和快捷启动工具更合适，工作台在这方面没有优势。

它的另一个取舍是功能更少：不做账号、不做同步、不做插件系统、不做脚本引擎。每一个都会把「一个下午能配好」变成「一个周末」。

怎么反馈问题？

到 GitHub Issues 提交，附上系统版本、哪个场景、以及体检结果里显示的那一行字。

English

What is it for

It stores a set of things you want to open together (apps, local files or folders, and web addresses) as a scene. Before entering, it checks whether those addresses are reachable; when you leave, you leave a sentence behind as a handoff note, and the next time you come in the first thing you see is where you stopped.

How do I use it

Click the menu bar icon to open the panel. It lists your scenes, and clicking one enters it. In Settings you can assign hotkeys to scenes, up to nine, matching the first nine in the list.

What does entering a scene actually do

It works in a fixed order: apps first, then files, then web pages. Starting the apps first means files can be handed to them, and pages open last so the browser does not steal focus earlier. Apps that are already running are not launched again, so entering the same scene repeatedly is safe.

What is the check that runs before entering

It sends one probe request per address in the scene and disconnects as soon as the response headers arrive, reading none of the body (this is not a full page download that gets discarded). It then tells you what to do next based on why something failed:

ResultUsually meansBlocks you
UpThe service is reachableNo
Needs sign-in (401 / 403 / 407)The service is reachable; it just requires a loginNo, entry proceeds
Rate limited (429)Too many requests, but the service is thereNo
Gone (404 / 410)The path changedNo, warned only
Rejected (other 4xx)The other end refused this requestNo, warned only
Server error (5xx)The service is there but something is broken on its sideNo, warned only
DNS failureThe name will not resolve, most often because you are off the intranet or VPNYes
Cannot connectThe service is down, or the address is wrongYes
Certificate failureA proxy is intercepting the connectionYes
Timed outNo answer within six secondsYes
OfflineThis computer has no network connectionYes

Only the definitively unreachable cases block, and by default the item is not opened in those cases either, because it would only be an error page in the browser. Everything else goes through with the result marked.

Treating "needs sign-in" as healthy is deliberate. Mistaking a login wall for an outage is exactly what makes people stop trusting the feature.

What is a handoff note

The sentence you leave when you exit a scene, plus a snapshot of the state at that moment. The snapshot records exactly one thing: which of the scene's apps were still running and which had quit. It does not record browser tabs, because it cannot see them and does not pretend to. Each scene keeps its five most recent notes.

How many scenes and items can I have

Up to 60 scenes, and up to 40 items in a scene. Entering more than 12 items at once warns you first, though you can still continue. These limits exist to prevent the self-inflicted wound of opening 60 tabs with one click.

Where is my data, and what if I change computers

The whole document is a single JSON stored locally. There is no cloud, no sync, no iCloud. That is why the backup page puts export front and centre: it produces a plain-text JSON you can read and edit yourself. Import only merges, never clears, so importing a file will not wipe the scenes you already have.

Will I lose my data if I uninstall

Yes. The data exists only on this computer, uninstalling removes it, and there is no copy elsewhere. Export first if you want to keep it.

What permissions does it need

None, and it never shows a permission prompt. One point worth calling out: it needs no Accessibility and no Input Monitoring, because the global hotkeys go through the system's hotkey registration. It also does not control other apps' windows: no window layout, no moving windows, no synthetic clicks. See the Privacy Policy.

Does it go online

In one place only: the connectivity check, meaning the automatic check before entering a scene and the one you trigger yourself. That request goes only to addresses you typed into your own scenes. The app contains no server of ours, no analytics, no update check and no crash reporting. It is a GET with a Range header asking for a single byte, disconnected at the response headers; the session is ephemeral with cookies and the disk cache off, so which addresses you checked leaves nothing behind on this computer.

If I pick a local file, does it read the contents

No. Choosing the file happens in a system panel, done by you; the app does not go looking through your disk and has no directory-scanning feature. The credential it stores is read-only and exists for one purpose: handing the item to the system to open next time, the equivalent of you double-clicking it.

Why does it close when I click elsewhere

Because the panel is a transient popover, which is normal behaviour for a menu bar app. The cost is that long-lived uses were not optimised for: if you want to read the check results while copying something from elsewhere, the panel will close first. Stated plainly rather than glossed over.

Which systems are supported

macOS 14.0 or later. It is a menu bar app with no Dock icon.

Known gaps

These are the author's own notes, listed here rather than hidden:

  • There is no click-level end-to-end verification. The demonstration hooks exercise the real code paths (real probes, real entry logic), but the act of physically clicking the button has not been verified.
  • The paths with system dialogs are entirely unverified: choosing a file, choosing an app, exporting, importing, because all four raise a permission panel. If you hit trouble on one of those, it is very likely an uncovered path, and reporting it would help.
  • Long stays in the panel are not accommodated, since it closes as soon as you click elsewhere.

The app itself is feature complete with nothing half-finished; the above describes what has not been verified, not what has not been built.

Positioning, stated honestly

The difference this app makes is narrow. It matters to people who have to confirm a set of intranet or online services before starting work: operations, backend developers, anyone on a VPN, anyone maintaining several environments at once. If all you want is to open a few pages quickly, a general-purpose launcher is the better tool and Workbench offers no advantage there.

The other trade-off is fewer features: no account, no sync, no plugin system, no scripting engine. Each of those would turn an afternoon of setup into a weekend of it.

Reporting a problem

File an issue at GitHub Issues with your system version, which scene, and the line the check reported.
